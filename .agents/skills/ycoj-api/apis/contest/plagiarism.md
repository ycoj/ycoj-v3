# Contest C++ plagiarism checks

The contest plagiarism endpoints return JSON directly. They run similarity analysis as a persistent asynchronous job over the shared `background_task` store. CPU work runs in an isolated worker, while administrators can poll progress or reopen the completed report. This feature does not change submissions, judge scores, contest rankings, or user accounts.

## Authorization and eligibility

Every endpoint loads the current contest in the selected domain and requires its owner/maintainer (`user.own(tdoc)`) or `PERM_EDIT_CONTEST`. Contest participation, record-code permission, and `allowViewCode` do not grant access to these endpoints. The global contest must have ended according to `contest.isDone(tdoc)` without a participant status; finishing an individual timed attempt early does not allow a check.

All paths support the usual `/d/{domainId}` prefix. Authenticate with `Cookie: sid=...` or `Authorization: Bearer {sid}`, and send `Accept: application/json`. Route `tid` and source `rid` parameters must be 24-hex ObjectIds; `jobId` is a string generated by the server. Identifiers are taken from the route, rather than overridable query/body fields.

The asynchronous job supports up to 20 distinct participants and four distinct contest problems. A larger contest produces a failed job with an explanatory `error`; it does not silently truncate the participant or problem set. At most 80 representative sources and 760 cross-user pairs are analyzed.

## Routes and requests

| Method/path | Request type | Successful response |
| --- | --- | --- |
| `GET /contest/:tid/plagiarism` | No body | HTTP 200 `{ tdoc: Tdoc, job: PlagiarismJob \| null }` |
| `POST /contest/:tid/plagiarism` | Empty JSON object `{}`; no `operation` field | HTTP 202 `PlagiarismJob` |
| `GET /contest/:tid/plagiarism/:jobId` | No body | HTTP 200 `PlagiarismJob` |
| `GET /contest/:tid/plagiarism/:jobId/source/:rid` | No body | HTTP 200 `PlagiarismSource` |

The initial GET returns the latest non-expired job for this contest, shared among all authorized managers. POST admits a new job or returns the existing pending/running job for the same contest, including across concurrent requests and server workers. Four contest plagiarism tasks can run concurrently across the shared pool. When the pool is full and this contest has no active task to reuse, POST returns `PlagiarismCapacityError` (HTTP 503) and does not queue another task. A completed or failed task can be rerun with another POST.

Example requests:

```http
POST /d/school/contest/665f00000000000000000001/plagiarism
Accept: application/json
Content-Type: application/json

{}
```

```http
GET /d/school/contest/665f00000000000000000001/plagiarism/4d548c56-28fc-4cf2-881c-a0f636466f59
Accept: application/json
```

```http
GET /d/school/contest/665f00000000000000000001/plagiarism/4d548c56-28fc-4cf2-881c-a0f636466f59/source/6ac992c00000000000000000
Accept: application/json
```

## Response types

All dates are ISO-8601 strings. All similarity scores are percentages in `[0, 100]`, not probabilities of cheating. Match line ranges are inclusive and one-based in the original source snapshot.

```ts
type PlagiarismJob = {
  jobId: string;
  status: 'pending' | 'running' | 'completed' | 'failed';
  createdAt: string;
  progress?: { completedPairs: number; totalPairs: number };
  result?: PlagiarismReport; // present only when completed
  error?: string; // present only when failed
};

type PlagiarismParticipant = {
  rid: string;
  uid: number;
  language: string;
  submittedAt: string;
  tokenCount: number;
};

type PlagiarismReport = {
  version: string; // engine version used for this snapshot
  generatedAt: string;
  elapsedMs: number;
  participantCount: number; // distinct attending or submitting users, including skipped sources
  submissionCount: number; // representative sources successfully analyzed
  comparedPairs: number;
  skippedSubmissions: Array<{ rid: string; uid: number; pid: number; reason: string }>;
  users: Record<number, { _id: number; uname: string; displayName?: string }>;
  problems: Array<{
    pid: number;
    title: string;
    submissionCount: number;
    participantCount: number; // users with successfully analyzed sources for this problem
    comparedPairs: number;
  }>;
  pairs: Array<{
    pid: number;
    left: PlagiarismParticipant;
    right: PlagiarismParticipant;
    similarity: number;
    scores: { token: number; structure: number; fingerprint: number };
    matches: Array<{
      leftStartLine: number; leftEndLine: number;
      rightStartLine: number; rightEndLine: number;
      tokenCount: number;
    }>;
    warnings: string[];
  }>;
};

type PlagiarismSource = {
  rid: string;
  uid: number;
  pid: number;
  code: string;
  language: string;
};
```

## Selection, algorithm, and resource behavior

The job captures the contest's problem IDs and global start/end times when admitted. It selects one latest C++ record (`cc` or `cc.*`) per user/problem in that contest and domain, regardless of judge outcome. A later non-C++ submission does not replace an earlier C++ submission. If a user/problem has only unsupported-language submissions, its latest submission is listed in `skippedSubmissions`. Canceled records, hack records/targets, other contests/domains/problems, pretests, and record-history revisions are excluded. Submission times come from ObjectId timestamps, which have one-second precision; selection uses timestamp buckets intersecting the contest window. Submissions made after the contest window, including later bulk imports, are excluded.

Inline and `files.code` storage-backed code are supported. Sources are bounded to 64 KiB each; empty, missing, unreadable, or over-limit sources are listed as skipped with an explicit reason. Tokenization-limit failures are also skipped. Each valid source is analyzed once; only different users' sources for the same problem are paired. The report includes all those pairs, sorted by descending similarity, with separate normalized token, statement-structure, and winnowed-fingerprint scores. The engine ignores comments/whitespace, canonicalizes identifiers, drops conservative unused scalar declarations, and uses order-independent features for moved statements and helper extraction. It is a lexical similarity detector rather than a complete C++ compiler or a proof of misconduct.

Pair comparison has a two-second deadline. The entire asynchronous task has a five-minute deadline, including preparation. A pair timeout, worker crash, or computation failure fails the whole job rather than silently omitting a pair. Short code is capped at a lower aggregate similarity to reduce unsupported conclusions from common snippets. At most 16 largest matching regions per pair are returned; warnings indicate truncated evidence. Codes currently include `short-source`, `preprocessor-not-expanded`, `incomplete-comment`, `incomplete-raw-string`, `incomplete-string`, `unused-scalar-ignored`, and `evidence-regions-limited`.

Reports and accepted source snapshots are retained for 24 hours after completion. The source endpoint returns the immutable snapshot used for that report, rather than the current record content, and only for accepted report submissions in a completed job. Source requests for pending, running, failed, expired, unknown, cross-contest, or cross-domain references return `NotFoundError` (HTTP 404) after authorization. Job polling returns in-flight/failed states normally, but expired, unknown, cross-contest, or cross-domain jobs return HTTP 404. Failed task sources are cleared. Jobs abandoned by a restarted worker eventually become failed through timeout reads or periodic cleanup; they are not automatically recomputed.

Permission failures return `PermissionError` (HTTP 403); a live contest returns `ContestNotEndedError` (HTTP 403); invalid decorated identifiers return `ValidationError`. Errors use the usual `{ "error": { "name", "params", "code" } }` envelope. Expected size/deadline failures are summarized in a failed job's string `error`; unexpected internal exceptions are logged privately and produce a generic failed-job message.

For the recommended request sequence and stopping conditions, see [the plagiarism-check workflow](../../workflows/check-contest-plagiarism.md).
