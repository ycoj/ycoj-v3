# Run and review a contest plagiarism check

Use the [contest plagiarism contract](../apis/contest/plagiarism.md). Every request needs an account that owns/maintains the contest or has `PERM_EDIT_CONTEST`; contestant access and record-code permissions are insufficient.

1. Resolve the deployment, domain, contest ID, and authorized session. Send `GET /contest/:tid/plagiarism` with `Accept: application/json`. Verify the returned contest ID/title and that its global end time has passed. The endpoint itself enforces this condition. If a pending/running `job` already exists, reuse its `jobId` instead of starting another job. A completed report may be reused while it remains retained.
2. When a new check is requested, send `POST /contest/:tid/plagiarism` with `Content-Type: application/json` and body `{}`. Require HTTP 202 and retain the returned `jobId` and `createdAt`. The server returns the same active task for concurrent starts; a fresh check after completion/failure creates a different ID. On a validation, permission, or HTTP 503 capacity error, stop this attempt and surface that response.
3. Poll `GET /contest/:tid/plagiarism/:jobId` every two seconds. Render `pending`/`running` and optional `{completedPairs,totalPairs}` progress. Stop polling on `completed` or `failed`; failure has a user-readable `error` and no report. Stop on HTTP 404 or a permission error, rather than retrying indefinitely. The whole task expires into failure after five minutes if a worker cannot finish.
4. For `completed`, verify `result.version`, problem IDs, participant/submission counts, and `comparedPairs`. Review `skippedSubmissions` before interpreting coverage. Zero comparable pairs is a valid completed empty report. Scores are percentages in `[0,100]`; rank suspicious same-problem pairs and inspect the separate scores and warnings. Similarity alone does not establish misconduct.
5. To inspect a pair, fetch each side using `GET /contest/:tid/plagiarism/:jobId/source/:rid`. Validate that response `rid`, `uid`, and `pid` match the chosen report participant/problem. Display the returned snapshot code with the report's inclusive, one-based matching line ranges. Never substitute a live `/record` response, since it could differ from the analyzed snapshot. If the snapshot is unavailable, stop source loading and surface the HTTP error.
6. Reports/sources remain available for 24 hours after completion. A later POST recomputes a new report from eligible contest-window records. Running a check makes no disciplinary, judge-score, contest-ranking, or account changes. Stop after the requested report/source review is delivered; any resulting administrative decision is separate work.
